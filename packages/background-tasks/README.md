# Background tasks

Non-interactive shell commands whose lifetime is **limited to the current Pi session**. Load the package with `pi -e .`. In TUI mode, the shared `activity-indicator` widget shows active tasks alongside subagents; without it, a standalone widget shows the task count.

`/ps` opens a **full-page** list with two sections, “Running” and “Finished”, each sorted by descending start time. Markers and colors distinguish active (●), successful (✓), failed (✗), and stopped or timed-out (■) tasks. Finished tasks remain available until the session ends. `/ps` accepts no arguments or subcommands. Outside TUI mode, it lists tasks through a notification when the interface supports it. The agent still uses `task_status`, `task_output`, and `task_stop`; tools remain available in every Pi mode.

Every task requires a free-form, non-blank title of at most 80 Unicode characters, with surrounding whitespace trimmed. The list displays the title instead of the command. The detail header includes the title, abbreviated ID, state, duration, and shell PID; the command appears on the next line for diagnostics. The PID is not necessarily a child process PID and remains historical information after completion, not proof that the process is still running. Durations update while tasks run and freeze at completion. A blank line separates list sections, and another separates detail metadata from output tabs.

Both views resize with the terminal and temporarily cover the conversation and editor without replacing them. Enter opens live logs on the `stdout` tab; `t` or Tab switches to `stderr`, with byte counters for each stream. ↑↓ and PgUp/PgDn scroll; ↑ loads older retained pages, Home jumps to the beginning of the loaded window, and End returns to the live tail. `s` stops an active task from either view without closing it. Esc returns to the list, then closes it. Scrolling upward pauses automatic following; reaching the end or pressing End resumes it. Switching tabs jumps to the selected stream’s tail.

The displayed help is deliberately short: “↑↓ select · Enter open · s stop · Esc close” in the list, and “↑↓ scroll · t switch stream · s stop · Esc back” in details. The stop hint only appears for active tasks. PgUp/PgDn, Home, End, and Tab remain available without appearing in the help.

In Pi **fullscreen** mode (`pi --tui-mode fullscreen`), the mouse wheel navigates the list and logs through Pi’s native support. Clicking does not open tasks or switch tabs. In regular mode, the terminal handles the wheel, so it does not scroll these views. No extra mouse adapter or capture is installed; all controls remain keyboard-accessible. The view keeps a bounded reading window: discarded display pages can be reread from the temporary file, and a warning appears when retention has removed the beginning of the log.

| Tool | Parameters | Result |
| --- | --- | --- |
| `task_start` | `title` (required free-form description, 1–80 characters, non-blank), `command` (shell, 1–4096 characters), `resume?` (boolean, default `false`), `timeoutMs?` (positive integer, maximum total runtime in ms) | Starts immediately in the current directory and returns the ID, title, state, and start time. No interactive stdin. |
| `task_status` | `id?`, `offset?` (pagination index, default 0); without an ID: paginated list | `{tasks, total, nextOffset}` (20 tasks/page), or individual status, including title. Command preview limited to 200 characters; timestamps, shell PID, exit code, signal, produced bytes, truncation, and cleanup uncertainty. |
| `task_wait` | `id`, `timeoutMs` (0–300000 ms) | `{timedOut, task}`. An expired wait **never stops** the command. |
| `task_output` | `id`, `offset?` (absolute byte position), `maxBytes?` (1–16384, default 16384), `stream?` (`combined` by default, `stdout`, `stderr`) | Without offset: log tail; with offset: forward page. Continue with `nextOffset`. UTF-8 boundaries are preserved: a 1–3 byte request may return up to 4 bytes for a complete character; an incomplete trailing character waits for more bytes (`nextOffset` may remain unchanged). `unavailableBefore`, `gap`, and `truncated` indicate lost data. Combined stdout/stderr ordering is not guaranteed; `stream` selects separate output. Offsets, truncation, and `unavailableBefore` belong to the selected stream. |
| `task_stop` | `id` | Stops the process group and observed descendant groups (TERM, then KILL), waits and verifies exit; retains status and logs until session shutdown. |

States: `running`, `completed` (exit 0), `failed` (nonzero exit or launch error), `stopped`, and `timed_out` (the `task_start` runtime limit). Exit code may be `null` when a signal killed the process; `signal` then records it. At most four admitted starts or processes awaiting verified exit are allowed (a `stopped` task still stopping occupies a slot). There is no queue or implicit timeout. Finished tasks remain inspectable until the session ends. If the main command exits but leaves observed descendants running, cleanup starts immediately rather than waiting for `/quit`; status and logs remain available.

At completion, Pi notifies the active interface. `resume: true` sends an agent follow-up, including on failure, without interrupting an ongoing turn. It contains the ID and state, **not logs**: the agent must call `task_output`. After `/tree` navigation, automatic resume is disabled for existing tasks; new tasks may request it again. `/compact` changes nothing. Session switching, `/reload`, and normal Pi shutdown stop commands and delete logs.

Logs are private: the temporary directory uses mode 0700 and files use 0600. The **latest 10 MiB per stream** (`combined`, `stdout`, `stderr`) are retained and deleted on shutdown, bounding disk usage at 30 MiB per task. Separate files preserve combined-output compatibility and allow independent pagination. The displayed window is limited to 64 KiB / 600 lines, and tool reads are bounded. Excerpts already included in Pi history are not removed from it.

Abrupt Pi termination (SIGKILL or machine crash) does not guarantee command termination or temporary-file removal; no cleanup daemon is installed. Observed descendants in separate process groups are also stopped and verified. Periodic observation cannot guarantee detection of a descendant that detaches **and loses its parent link between observations**, such as a very fast double-fork daemon: do not launch daemons with these tools. On POSIX systems, known process groups are verified through `/bin/ps`; failed observation or verification is reported through `cleanupUncertain`/`stopError` and a shutdown notification. Windows is not supported.
